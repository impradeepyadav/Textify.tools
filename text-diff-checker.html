What does this Text Diff Checker do?

This free online text diff checker compares two versions of text and shows you exactly what changed. Paste the original in the left panel and the modified version in the right, click Compare, and the tool highlights additions in green and deletions in red — instantly, with no server round-trip.

Unlike a simple character counter, a diff checker understands structure. It matches lines that stayed the same and only marks what actually changed. This makes it useful for reviewing code edits, checking document revisions, comparing configuration files, or spot-checking a translation. It is effectively a browser-based equivalent of the Unix diff command and the git diff output.

Everything runs locally in your browser. The texts you paste never leave your device, there is no signup, and there are no usage limits. Compare as many texts as you want, as many times as you want.

How to compare two texts and find differences

  1. Paste the original text into the left panel. This is your "before" version.
  2. Paste the modified text into the right panel. This is your "after" version.
  3. Choose comparison options. Pick line, word or character level. Toggle ignore whitespace and ignore case if you want to filter out noise.
  4. Click Compare. The diff engine highlights additions in green, deletions in red, and shows unchanged lines as context. The stats bar shows added, removed, unchanged counts and a similarity score.
  5. Switch views. Side-by-side shows original and modified in parallel columns. Unified combines both into a single column with + and - prefixes, like git diff.
  6. Copy or download. Copy the diff output to your clipboard or download it as a .diff file in standard unified diff format.

Line, word or character — which one should you use?

The comparison always starts by matching lines. The detail mode decides what gets marked inside a line that counts as changed.

Mode What it does Best for
Line Marks a changed line as a whole. Fastest option. Code, logs, config files, structured text where line breaks carry meaning
Word Highlights only the words that changed inside a line. Articles, contracts, translations, prose — the default choice for most text
Character Takes the difference down to single characters. Identifiers, hashes, long numbers, spotting a single changed digit or typo

If you are not sure, start with Word mode. It gives you the most useful level of detail for everyday text. Switch to Line for code and Character for precise edits.

How the diff algorithm works

This tool uses the Myers diff algorithm — the same algorithm behind git diff, GNU diff, and most professional diff tools. It is mathematically guaranteed to return the shortest list of changes that transforms one text into the other, so you are never shown a change that did not happen.

At a high level, the algorithm builds a table comparing both texts and finds the longest common subsequence (LCS). Everything outside that subsequence is either an addition or a deletion. When you enable character-level diff, the same algorithm runs a second time inside each changed line pair to pinpoint exactly which characters changed.

This is not a crude "line by line comparison" — it understands insertions, deletions and rearrangements, so the result is as accurate as the diff you would see in a version control system.

Text diff best practices

  • Use line mode for code. Line breaks carry meaning in code, logs and structured data. Line mode gives you the cleanest view.
  • Use word mode for prose. Articles, contracts and emails read better when only the changed words are highlighted.
  • Use character mode for precision. When a single digit in an ID, hash or version number matters, character mode catches it.
  • Ignore whitespace when indentation is noise. If one version uses tabs and the other uses spaces, turn on Ignore whitespace to focus on real changes.
  • Ignore case when capitalization is irrelevant. Useful for comparing data exports where case may differ but meaning is the same.
  • Download the .diff for sharing. The unified diff format is universally understood and can be applied with patch or git apply.
