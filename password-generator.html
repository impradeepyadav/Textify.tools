What is a password generator?

A password generator creates random passwords that are hard to guess. The whole point is to avoid patterns that humans naturally fall into — reuse, dictionary words, birthdays, keyboard walks like qwerty, and small substitutions like p@ssw0rd. A generated password has no meaning and no predictable structure, so the only realistic attack is brute force — trying every possible combination — and that becomes impossible once the password is long enough.

The passwords on this page are generated using your browser's cryptographically secure random number generator, crypto.getRandomValues. That is the same primitive your browser uses to build TLS session keys and CSRF tokens. We use rejection sampling to pick each character, which eliminates the subtle bias that a naive Math.random() * charset.length approach introduces.

Everything runs locally. No character of any password you generate is ever sent to a server, logged, or stored anywhere. Close the tab and it's gone.

How to generate a strong password

  1. Set the length. Use the slider or type a number. 16 characters is a good default for most accounts; 20 or more for email, banking, and anything that controls other accounts.
  2. Pick your character types. Uppercase, lowercase, numbers, and symbols all add entropy. If a site rejects one of these, turn it off and lengthen the password instead.
  3. Exclude similar or ambiguous characters if you type by hand. Removing I, l, 1, O, 0 and confusing symbols prevents typos at a tiny cost to entropy.
  4. Choose how many. Generate one password for a single account, or up to fifty at once for a batch of new accounts. Enable “Avoid duplicates” so the batch contains no repeats.
  5. Pick an output format. Plain text for pasting, JSON array for use in a script, or CSV with a header for spreadsheets.
  6. Copy or download. Each password has its own copy button. Copy all copies the entire batch. Download saves a `.txt` or `.json` or `.csv` file depending on your format.
  7. Store it in a password manager. A generated password is only useful if you actually use it. Save it to a password manager before navigating away.

How strong is strong enough?

Password strength is really just a number: how many guesses does an attacker have to make to find your password by brute force? That number is called entropy and it is measured in bits. Each extra bit of entropy doubles the number of guesses required. The table below shows roughly how long a modern off-line attack would take to search a password space at one trillion guesses per second — a rate achievable with a handful of GPUs against a stolen hash dump.

Password lengthEntropy (mixed character set)Time to crack (offline)Recommendation
6 characters~39 bitsSecondsNever use
8 characters~52 bitsHoursToo weak
10 characters~65 bitsWeeksToo weak for real accounts
12 characters~78 bitsYearsMinimum for low-risk sites
16 characters~105 bitsMillions of yearsRecommended for most accounts
20+ characters~131+ bitsAstronomically longEmail, banking, admin access

The most important thing you can do is increase length. A 20-character lowercase-only password has more entropy than an 8-character one that uses every possible character set. Length beats complexity almost every time.

Passwords you should never use

Every year, leaked password databases confirm the same thing: people reuse the same weak passwords across dozens of sites, and a single breach exposes thousands of accounts. If any of the following looks familiar, change it today — no password generator can help you if your habits undo the work.

  • Common passwords. password, 123456, qwerty, iloveyou, admin, letmein. These are always the first guesses in any attack.
  • Keyboard walks. asdfgh, qwertyuiop, 1qaz2wsx. Attackers have dictionaries of these patterns.
  • Personal details. Names, birthdays, pet names, sports teams, phone numbers. Anyone who can find your Instagram can guess half of these.
  • Substitution tricks. p@ssw0rd, l3tm3in, M0nkey!. Every serious attack tool includes a substitution dictionary that converts these back to the base word instantly.
  • Reused passwords. Even a strong password reused across ten sites becomes a liability the moment one of those sites is breached.
  • Short passwords. Anything under 12 characters, no matter how “random” it looks, can be broken.

This generator creates passwords in your browser, but it cannot store them. If you don't save the password to a password manager before closing the tab, you will never be able to recover it. Copy it, paste it into your password manager, verify it works, and only then move on.

Character sets and entropy

Each character set you add multiplies the number of possible passwords by its size. Symbols have the biggest effect per character, but the total entropy still comes mostly from length.

Character setSizeEntropy per character
Lowercase letters (a–z)26~4.7 bits
+ Uppercase letters (A–Z)52~5.7 bits
+ Numbers (0–9)62~5.95 bits
+ Symbols~90~6.5 bits

So a 16-character password drawn from the full set of lowercase, uppercase, numbers, and symbols has roughly 16 × 6.5 = 104 bits of entropy. A 12-character password from the same set has 78 bits. Both are difficult to brute force, but the difference is a factor of about 67 million — which is why length matters so much.
