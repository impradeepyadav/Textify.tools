What does the Text to CSV converter do?

This free online tool takes plain text where each line is a row and columns are separated by a delimiter — tab, comma, semicolon, pipe, or any custom character — and converts it into properly formatted CSV (Comma-Separated Values) that Excel, Google Sheets, Numbers, and any database import wizard can open.

Unlike a naive find-and-replace that just swaps one character for another, this converter does real CSV parsing and generation. It handles quoted fields, escapes internal double quotes per RFC 4180, and lets you control the output delimiter. So whether you're preparing a data export, cleaning up a log file, or building a spreadsheet from a copy-pasted list, the output will actually import correctly.

Everything runs locally in your browser using JavaScript. Your text never leaves your device — there is no server processing, no logging, and no data storage. Close the tab and it's gone.

How to convert text to CSV — step by step

  1. Paste your text: Drop tab-separated, comma-separated, pipe-separated, or space-separated rows into the input box. Each line becomes a CSV row.
  2. Pick the input delimiter: Choose the character that separates columns in your source data. Or let Auto-detect figure it out from the first few lines.
  3. Pick the output delimiter: Comma is the standard CSV format. Use semicolon for European locales where commas are decimal separators, tab for TSV, or pipe if your target system expects it.
  4. Set options: Add a header row (Column1, Column2, …), enable RFC 4180 quoting, skip blank lines, and trim whitespace per field.
  5. Click Convert to CSV: The tool parses your text and shows the result instantly, with row and column counts.
  6. Copy or download: Use the Copy CSV button or download the result as a .csv file ready for Excel, Google Sheets, or any database import.

Shortcut: Press Ctrl + Enter (or Cmd + Enter on Mac) inside the input box to convert instantly.

CSV format rules — what RFC 4180 says

CSV looks simple, but there are a few rules that matter if you want your file to import correctly everywhere. This tool follows them all.

  • Fields are separated by the delimiter — usually a comma, but the spec allows others.
  • Records are one per line, separated by CRLF (or LF in modern usage).
  • Fields containing a comma, quote, or newline MUST be wrapped in double quotes. Our tool does this automatically when quoting is enabled.
  • Double quotes inside a quoted field are escaped by doubling them. For example, He said "hi" becomes "He said ""hi""" in the CSV.
  • Leading and trailing whitespace is significant inside quoted fields. Our optional trim removes it if you want clean output.

If you need a formal reference, the rules are defined in RFC 4180.

Tips and best practices

  • Check your source delimiter first. If you're not sure, try Auto-detect. If it guesses wrong, pick manually — the answer is usually obvious once you look at the input.
  • Use semicolon output for European Excel. Excel in many EU locales uses a comma as decimal separator and expects semicolons to delimit fields. If opening the CSV puts everything in column A, try semicolon output.
  • Keep quoting on unless you're sure you don't need it. It's the difference between a file that imports cleanly and one that has columns shifting around because a field contained a comma.
  • Normalise whitespace first if the input is messy. If your text uses multiple spaces as separators, run it through the Whitespace Cleaner first, then come back and convert.
  • Use Trim whitespace for spreadsheet imports. Extra leading/trailing spaces can make lookups fail in Excel and Sheets. Trimming usually avoids that.
  • Preview with a small sample. Convert one or two rows first, check the output looks right, then paste the full dataset.
  • Need the reverse? Try the CSV to Text tool to go from CSV back to plain columns.
  • Watch out for leading zeros. Excel strips leading zeros from numbers when importing CSV. If you have codes like 007, keep quoting on and import as text, or prefix the values with an apostrophe.

Privacy, accuracy, and limits

Privacy: Nothing you paste into this converter is sent to a server. The whole parser and CSV writer is JavaScript that runs entirely in your browser tab. There is no upload, no queue, no analytics event that includes your text, and no server-side log.

Accuracy: The converter follows RFC 4180 for quoting and escaping. Auto-detect inspects the first few lines and picks the delimiter that appears consistently most often. That works for the vast majority of real-world input. If auto-detect guesses wrong, pick the delimiter manually — the output updates instantly.

Limits: There is no hard limit on input size. Since everything runs in-browser, the practical limit is your device's memory. Tens of thousands of rows process in well under a second. Very large pastes (multiple megabytes) may take a moment.
