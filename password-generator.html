What is a password generator?

A password generator creates random passwords that are hard to guess and hard to crack. The best ones use a cryptographically secure pseudorandom number generator (CSPRNG) rather than a general-purpose PRNG like Math.random, because a non-cryptographic PRNG can be predicted from a small amount of output. This tool uses the browser's crypto.getRandomValues API, which is backed by the operating system's CSPRNG.

The generator also uses rejection sampling to eliminate modulo bias. A naive implementation that does randomValue % charsetSize is slightly biased toward the first few characters of the charset, because the range of the random value is not an exact multiple of the charset size. Rejection sampling discards the small tail of values that would introduce bias, giving every character in the charset an equal probability of being selected.

The generator guarantees at least one character from every selected character set. If you enable uppercase, lowercase, numbers, and symbols, the password is guaranteed to contain at least one of each. This satisfies complexity requirements that ask for "at least one uppercase, one number, and one symbol" while still producing a uniformly random password overall.

How long should a password be?

Length matters far more than complexity. A long password made only of lowercase letters can be stronger than a short password with symbols and mixed case. The strength meter above shows entropy in bits, calculated as length × log₂(charset size).

For most accounts, 16 characters with a full charset is a reasonable default. For high-value accounts (email, banking, your password manager), use 20 or more. For passwords you actually type by hand, use a longer passphrase rather than a shorter complex password.

How this generator stays secure

Every password generator claims to be secure. Here is what the code actually does:

  • Uses crypto.getRandomValues — the browser's CSPRNG, backed by the OS entropy pool. Never uses Math.random, which is predictable.
  • Rejection sampling for unbiased selection — after generating a random 32-bit value, the code discards it if it falls in the bias-inducing tail, then retries. Every character has exactly equal probability.
  • Guarantees one character per set — if you select multiple character sets, the password is guaranteed to include at least one from each. The remaining characters are drawn from the union of all selected sets.
  • Securely shuffles — the guaranteed characters and the remaining characters are combined and then shuffled with a Fisher–Yates shuffle driven by the same CSPRNG, so the required characters don't end up at predictable positions.
  • Runs entirely in the browser — no network requests, no server, no logging. The password exists only in your tab's memory until you copy it.

What this tool does not do: it does not store the passwords for you. Copy them into a password manager immediately. Your browser's clipboard is accessible to any page or script on the same origin — do not leave the password on the clipboard longer than necessary.

Password hygiene that matters more than generation

A perfectly random password is worthless if you reuse it, store it in plaintext, or type it into a phishing page. The basics:

  • Use a password manager. Bitwarden, 1Password, KeePassXC, and iCloud Keychain all work. The manager is what makes it practical to have a unique 20-character password on every site.
  • Never reuse passwords. One breach should not compromise all your accounts.
  • Enable two-factor authentication. Prefer authenticator apps or hardware keys over SMS.
  • Use a longer, unique password for the password manager itself. This is the one password you need to memorize. Use a 4–6 word passphrase generated from a wordlist, or a very long random string kept on paper in a safe.
  • Don't type passwords into links you received — go to the site directly instead.
