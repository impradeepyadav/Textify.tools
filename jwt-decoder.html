What is a JWT decoder?

A JSON Web Token is three Base64URL-encoded strings joined by dots. The first two are plain JSON — the header and the payload — and can be decoded by anyone. The third is a cryptographic signature that lets a server check the first two haven't been tampered with, but it can't be verified without the signing key.

This tool splits the token, decodes the header and payload from Base64URL, and pretty-prints the JSON so you can read it. It's the fastest way to answer questions like "what's in this token?", "which algorithm signed it?", and "has it expired yet?" without writing a script or spinning up a server-side debugger.

Everything runs locally in your browser. The token you paste never leaves your device, there's no signup, and there are no usage limits.

Why signature verification is not performed

Verifying a JWT signature requires the secret or public key that was used to sign it. That key is one of the most sensitive pieces of configuration in any system — with it, an attacker can mint valid tokens for any user. Sending it to a browser tool, or storing it in a web page's memory, would be a serious security regression.

So this tool deliberately stops at decoding. It tells you what a token claims, not whether those claims are trustworthy. For actual verification, do it on your server with the same key that issued the token, using a library like jsonwebtoken in Node, PyJWT in Python, or jose in Go.

Decoding without verifying is still useful: you can check that the right claims are present, spot a misconfigured issuer, or confirm that a token has the scopes you expect before it reaches a real verifier.

Registered claims and what they mean

The JWT spec defines seven "registered" claims. Any other field in the payload is a custom claim defined by the application that issued the token.

ClaimFull nameWhat it means
issIssuerWho created and signed the token. Usually a domain or service identifier.
subSubjectWho the token is about. Typically a user ID.
audAudienceWho the token is intended for. A server should reject tokens whose aud doesn't match its own identifier.
expExpiration timeUnix timestamp after which the token must be rejected.
nbfNot beforeUnix timestamp before which the token must be rejected.
iatIssued atUnix timestamp of when the token was created.
jtiJWT IDA unique identifier for the token, useful for revocation lists.

This tool shows every claim in the payload, with its registered meaning where one exists, and converts exp, nbf, and iat from Unix timestamps to readable dates automatically.
