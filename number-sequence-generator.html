What does this Number Sequence Generator do?

A number sequence generator produces a list of numbers that follow a rule. The three classic rules are arithmetic (add a constant step: 1, 4, 7, 10), geometric (multiply by a constant ratio: 2, 4, 8, 16), and Fibonacci (each term is the sum of the previous two: 1, 1, 2, 3, 5, 8). This tool also generates prime numbers, square numbers, and custom ranges with a step, which covers almost every sequence you would need for test data, worksheets, or exploration.

Once generated, you get the sequence as a comma list, a space list, a newline list, a JSON array, or a true CSV row. The tool also computes the count, the first and last terms, and the sum, so you can sanity-check a long sequence without scrolling through it.

Everything runs locally in your browser. Nothing is uploaded, and no account is needed.

How to generate a number sequence

  1. Pick a sequence type: Arithmetic, Geometric, Fibonacci, Primes, Squares, or Range.
  2. Set the parameters: Enter a start value and a step or ratio. For Fibonacci, primes, and squares, you only need the number of terms.
  3. Choose an output format: Comma, space, newline, JSON array, or CSV row.
  4. Click Generate Sequence: The result appears instantly, along with the count, first term, last term, and sum.
  5. Copy or download: Copy the formatted sequence, or download it as a CSV file with an index column.

How the generator keeps results exact

JavaScript numbers are doubles, and integers above 2^53 lose precision silently. That matters for Fibonacci (the 79th term is already above 2^53) and for large ID ranges. This tool detects when every input is an integer and switches the sequence engine to BigInt, so the terms are exact strings instead of rounded doubles.

For decimal inputs, the tool uses floating-point arithmetic but formats each term to 10 decimal places and strips trailing zeros, which avoids the classic 0.1 + 0.2 = 0.30000000000000004 display problem.

Prime mode uses a Sieve of Eratosthenes with an estimated upper bound, then extends the sieve if the estimate falls short. That keeps it fast for both small and large prime counts.
